# Начальник отдела и календарь по отделу

Поиск начальника и фильтрация календаря выполняются исключительно по локальной БД BookHR. Клиент и воркер внешнего справочника не изменены. Открытие плана или календаря не вызывает синхронизацию.

Ключ отдела — сохранённый `Employment.formal_department_short_name`: точное равенство после нормализации пробелов и регистра. Это единый источник для обеих функций. Проверьте реальные значения этого поля перед включением: приложение не извлекает номер из полного названия, не объединяет `01` и `1`, не использует номер карточки. Если внешний сервис сохраняет здесь не требуемое обозначение отдела, потребуется отдельно уточнить источник номера; текущая версия не меняет внешний контракт.

Начальник — единственный активный сотрудник своей компании и отдела с актуальной полной должностью, начинающейся с «Начальник отдела». Заместитель и сам сотрудник исключаются. При нескольких кандидатах выводится неоднозначность. Начальник должен присутствовать в локальной базе. Фактический грейд берётся из BookHR, не из внешнего сервиса.

## Установка

1. Сделайте резервную копию БД.
2. Обновите backend, примените миграцию `0026_user_employment` обычным скриптом проекта и обновите сборку frontend.
3. Viewer автоматически привязывается при успешном входе или загрузке `/api/me`, если полное ФИО учётной записи совпало ровно с одним действующим трудоустройством своей компании. Для дублей и несовпадений используйте «Настройки → Пользователи → Сотрудник для календаря отдела». Поиск серверный, есть страницы.
4. Проверьте отделы и доступ с двумя viewer из разных отделов.

Ручная привязка доступна только администратору. Автоматическая работает для существующих и новых локальных/LDAP viewer: сравниваются все компоненты полного ФИО без учёта регистра и лишних пробелов. Инициалы, частичное совпадение и нечёткий поиск не используются; «ё» и «е» различаются. Грейд не участвует. Существующая привязка не заменяется, admin/hr автоматически не привязываются. Изменение записывается в аудит один раз. Внешний кадровый сервис не вызывается. До привязки, после увольнения или при пустом отделе календарь viewer пуст. При удалении сотрудника связь очищается. После повторного приёма при сохранённой старой привязке администратор выбирает новое трудоустройство. Снятие привязки вручную не запрещает последующую автоматическую привязку по единственному совпадению.

Viewer может читать события своего отдела, включая ближайшие, просроченные и карточки событий. Чужой ID возвращает 404, изменение событий запрещено. События без сотрудника скрыты. Отдел определяется по текущим сохранённым данным, включая исторические события. При переводе доступ меняется со следующего запроса. В панели «Требует внимания» viewer получает только события; остальные кадровые категории не раскрываются.

Календарь доступен viewer из меню и по `/`, стартовая страница после входа остаётся «Сотрудники». Права других разделов и редактирования собственного плана онбординга сохраняются.

## DOCX

В начале шаблона используйте `{{ employee_position }}` и `{{ employee_name }}`. ФИО выводится как «Фамилия И.О.».

Внизу документа вставьте:

```
Начальник отдела
{{ department_head_position }}
{{ department_head_name }}
Грейд: {{ department_head_grade }}
```

В автоматически создаваемом шаблоне этот блок добавлен после этапов. Пользовательские шаблоны не перестраиваются: положение задаётся плейсхолдерами. Старые шаблоны работают. Если начальник не найден, переменные содержат «—», причина показана в окне плана.

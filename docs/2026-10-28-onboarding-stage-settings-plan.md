## 1. Выбранный вариант и границы задачи

Выбран первый десктопный вариант: **широкая модалка с таблицей и отдельным модальным окном добавления/редактирования этапа**. Боковая форма не используется.

Изменяется окно «Настройка этапов и полей», открываемое из раздела ввода сотрудников в должность. В текущем коде страница называется «План обучения» и имеет подпись «Ввод сотрудников в должность». Переименование раздела в эту задачу не входит.

Результат:

- Увеличенная ширина основного окна.
- Поиск по таблице.
- Прокрутка таблицы внутри окна.
- Выделенная закреплённая шапка таблицы.
- Шесть информационных столбцов и компактное меню действий каждой строки.
- Кнопка «Добавить этап» открывает отдельную форму.
- После успешного сохранения показываются доступные плейсхолдеры даты и отдела для Word.
- Кнопки скачивания и загрузки общего DOCX-шаблона плана в форме этапа.
- Оформление использует существующую дизайн-систему BookHR.

## 4. Основная модалка

### Размеры и компоновка

- Целевая ширина: `min(1440px, 95vw)`.
- Максимальная высота: `calc(100dvh - 2rem)`; окно центрировано.
- Вертикальная flex-компоновка: заголовок → пояснение и поиск/кнопка → область таблицы → нижняя панель.
- Прокручивается область таблицы; заголовок окна, поиск и нижняя панель остаются на месте.
- Контейнеры таблицы имеют `min-height: 0` и `min-width: 0`, чтобы прокрутка не увеличивала окно.
- На desktop 1440×900 и 1920×1080 все столбцы должны помещаться без горизонтальной прокрутки. На 1366×768 сохранить читаемость, при необходимости разрешить горизонтальную прокрутку только таблицы.
- При увеличении масштаба и на узком экране окно остаётся в пределах viewport; таблица прокручивается, кнопки доступны.

### Столбцы

1. Название.
2. Ответственный отдел.
3. Тип.
4. Соответствует этапу в документе.
5. Плейсхолдер даты.
6. Плейсхолдер отдела.
7. Узкая служебная колонка с кнопкой «бургер».

Показывать название пункта документа из каталога, а не технический ключ. Пустые отделы и недоступные плейсхолдеры обозначать «—». Для несопоставленного этапа писать «Не сопоставлен». Архивные строки сохранять в таблице с явной текстовой отметкой.

Плейсхолдеры показывать моноширинным текстом целиком, с возможностью копирования. Копировать двойные фигурные скобки и точное имя переменной; при недоступном Clipboard API дать выделить текст и скопировать вручную.

### Поиск

- Локальная фильтрация уже загруженного списка, без новых запросов на каждую букву.
- Искать по названию, отделу, отображаемому типу, названию пункта документа и именам плейсхолдеров.
- Игнорировать регистр и крайние пробелы; очистка запроса возвращает полный список.
- Показывать «Показано N из M» и состояние «Ничего не найдено».
- Поиск не меняет сохранённый порядок и не скрывает архивные записи дополнительным неявным фильтром.

### Sticky-шапка и меню строки

- Использовать семантическую таблицу и `thead th { position: sticky; top: 0; }`.
- Шапка имеет непрозрачную заливку и находится над строками.
- «Бургер» открывает меню возле выбранной строки с действиями: изменить, вверх, вниз, архивировать/восстановить, удалить.
- Сохранить действующие подтверждения архивирования и удаления с preview/snapshot.
- Неактивные крайние перемещения заблокированы; во время запросов исключить повторные операции.
- Перемещение при активном поиске выполняется относительно полного исходного порядка, на один шаг; в меню пояснять «в общем списке». Не отправлять на сервер только отфильтрованные строки.
- Меню не должно обрезаться scroll-контейнером. Предусмотреть отдельный слой и позиционирование в пределах viewport; закрывать при прокрутке, внешнем клике и Escape.
- Поддержать клавиатуру, доступное название кнопки, `aria-expanded` и возврат фокуса на «бургер».

## 5. Добавление и редактирование этапа

Кнопка «Добавить этап» открывает отдельную модалку поверх основной, ориентировочно 600–680 px шириной. Основная таблица сохраняет запрос поиска и положение прокрутки.

Состав формы:

1. «Название этапа» — обязательное поле, до 256 символов, проверка пустого значения после trim.
2. «Ответственный отдел» — существующее текстовое поле, до 256 символов.
3. «Тип» — Текст / Дата / Этап с датами / Этап без даты.
4. «Соответствует этапу в документе» — каталог и вариант «Не сопоставлен».
5. «Скачать шаблон».
6. «Загрузить шаблон».
7. «Отмена» и основная кнопка «Добавить этап» / «Сохранить».

Сопоставление активно только для типа «Этап с датами». Для других типов показать причину недоступности и не отправлять старое сопоставление в API. Сохранить серверную проверку запрета изменения типа заполненного поля и уникальности сопоставления.

Форма редактирования переиспользует те же поля. Предлагаемое имя нового компонента: `OnboardingColumnEditorModal.vue`.

После успешного создания:

- Обновить список и закрыть форму.
- В основной модалке показать название созданного этапа и блок «Плейсхолдеры для DOCX».
- Для сопоставленного этапа вывести отдельно «Дата этапа» и «Ответственный отдел», с копированием.
- Пример: `{{ pass_planned_date }}` и `{{ pass_department }}`.
- Имена получать из фактического серверного словаря переменных по источникам `stages.<key>.planned_date` и `stages.<key>.department`; не вычислять из русского названия и не полагаться только на суффиксы.
- Для несопоставленного этапа или неподдерживаемого типа показать понятную причину отсутствия переменных. Не выдавать фиктивные метки, которые сломают выгрузку.
- Если созданный этап не попадает под текущий поиск, сохранить поиск и оставить блок успешного создания видимым.

При ошибке форма и ввод остаются открыты. Для конфликта версии 409 сохранить ввод, обновить список и запретить повторное сохранение устаревшей версии до повторного открытия актуальной записи.

Сохранить подтверждение потери черновика. Escape закрывает только верхний слой; обработчик не должен одновременно закрывать основное окно. Использовать существующие `useFocusTrap` и `useBodyScrollLock`, проверить вложенные модалки и восстановление фокуса.

## 6. DOCX: плейсхолдеры и управление шаблоном

### Плейсхолдеры

Расширить ответ каталога этапов документа сведениями о реальных плейсхолдерах даты и отдела, оставив `key` и `title` совместимыми с текущими потребителями. Обновить тип ответа в frontend.

Произвольное создание новых пунктов `stages.json` через UI в эту задачу не включается. При реализации сохранить существующий каталог; создание поля и создание пункта документа — разные операции. Для нового поля, сопоставленного с доступным пунктом, плейсхолдеры появляются сразу после сохранения.

Не менять смысл выгрузки: дата — плановая в формате ДД.ММ.ГГГГ; отдел подставляется как `(отв 3 отдел)`, Times New Roman 12 pt курсивом, без изменения соседнего текста. Отдел без значения даёт пустой текст; неподставленная переменная отдела не добавляется в документ автоматически.

### Шаблон

Принята трактовка показанного варианта: кнопки относятся к **общему шаблону плана компании**, а не к отдельному файлу каждого этапа.

Это новая серверная функциональность. Предлагаемый контракт:

- `GET /api/onboarding/docx-template` — скачать действующий шаблон с незаполненными переменными.
- `POST /api/onboarding/docx-template` — загрузить/заменить шаблон компании через multipart.
- Доступ к этим операциям — HR/admin текущей компании.
- Версия шаблона передаётся при замене; конкурентная замена завершается 409 и не затирает чужой файл.

План серверной реализации:

1. Добавить хранение шаблона и его версии отдельно для каждой компании, с управляемым сервером путём. Конкретную таблицу/миграцию определить после проверки существующих настроек компании и актуальной цепочки миграций; номер миграции заранее не фиксировать.
2. Не перезаписывать общий файл из `ONBOARDING_DOCX_TEMPLATE` при загрузке из UI.
3. Единый выбор источника: загруженный шаблон компании → существующий серверный шаблон → базовый шаблон. Скачивание шаблона, выгрузка сохранённого плана и выгрузка из мастера используют один выбор источника.
4. Сохранить явную ошибку при неверном настроенном пути; не маскировать её незаметным переходом на базовый документ.
5. Проверять DOCX как ZIP/OOXML, ограничить размер файла и распакованных данных, проверить необходимые части и корректность XML; неизвестные переменные выявлять до активации. Использовать тот же разбор меток, включая разделённые Word runs, таблицы и колонтитулы.
6. Ошибка проверки оставляет предыдущий шаблон действующим. Замену выполнять атомарно, сохранить tenant isolation, CSRF и аудит изменения.
7. В форме явно подписать область действия: «Общий шаблон плана компании». Загрузка применяется отдельной операцией; отмена редактирования этапа не отменяет уже обновлённый шаблон. Показать успешный результат либо ошибку рядом с кнопками; черновик этапа сохранять.
8. Форма не требует загружать файл для каждого этапа. Шаблон можно скачать до создания этапа.

UI таблицы сам по себе не требует изменения модели этапов или существующих данных. Хранение загружаемых шаблонов — отдельная часть задачи с миграцией при необходимости.

## 8. Проверки и критерии приёмки

### Функциональные проверки

- Поиск по каждому информационному столбцу, очистка и отсутствие результатов.
- Создание/редактирование всех четырёх типов, сохранение отдела, сопоставления, ошибки и конфликты версий.
- Реальные плейсхолдеры в таблице и после добавления; копирование и ручной fallback.
- Перестановка с активным поиском и архивными строками; сервер получает весь список с актуальными версиями.
- Архивирование, восстановление и удаление сохраняют существующие проверки.
- Скачивание именно шаблона с метками; успешная и неуспешная загрузка; конкурирующая замена; отсутствие доступа к файлу другой компании.
- Валидный DOCX, повреждённый ZIP/XML, неизвестные переменные, превышение лимитов; прежний шаблон остаётся рабочим при ошибке.
- Выгрузка сохранённого плана и черновика мастера используют новый шаблон и сохраняют даты, стиль отдела, таблицы и колонтитулы.
- Проверки прав viewer/HR/admin и CSRF для новых операций.

### Визуальные и клавиатурные проверки

- 1366×768, 1440×900, 1920×1080, масштаб браузера 125% и 150%.
- Длинные названия, отделы, плейсхолдеры, много строк, пустой список.
- Шапка не просвечивает при прокрутке; меню и форма не обрезаются.
- Основное окно шире прежнего; на целевых широких экранах видны все столбцы.
- Tab/Shift+Tab не уходят в фон; Escape закрывает верхний слой; фокус возвращается инициатору.
- Несохранённые данные не теряются при ошибке, конфликте, обновлении списка или работе с шаблоном.
- Цвета, кнопки, радиусы, шрифты и отступы сверены с текущим приложением, без отдельной темы.

### Автоматизированная проверка

Добавить содержательные проверки в существующие frontend/backend наборы для фильтрации и порядка, вложенных диалогов, сопоставления переменных и операций шаблона. Не писать отдельные тесты на каждое CSS-значение.

Команды frontend из текущего `package.json`: `npm run typecheck`, `npm test`, `npm run build`. Backend — соответствующие pytest-наборы после уточнения текущих путей тестов. Для этой задачи подготовки плана тесты приложения не запускаются: код приложения не изменяется.

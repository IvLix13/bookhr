# Формат импорта Excel

Версия шаблона: `2.2`

Импорт доступен в двух режимах (вкладки на странице «Импорт»):

1. **Общая таблица** — сотрудники и связанные кадровые данные
2. **Поощрения** — записи модуля поощрений

---

## Общая таблица (`import_type=employees`)

### Обязательные колонки

| Колонка | Поле | Описание |
|---|---|---|
| ФИО | full_name | Полное имя сотрудника |
| Начало работы | hire_date | Текущий (последний) период работы. Формат `ДД.ММ.ГГГГ` или `14 ноября 2026 г.` |

Если заполнены колонки периодов (см. ниже), достаточно указать **Начало работы 1**; колонка **Начало работы** должна совпадать с началом последнего периода или может быть пустой.

### Дополнительные колонки

| Колонка | Поле |
|---|---|
| № п/п | row_num |
| Должность | title |
| Грейд по должности | position_grade |
| Фактический грейд | actual_grade |
| ВУЗ | education_status |
| Окончание договора | contract_end |
| Дата получения текущего грейда | grade_date |
| Начало работы 1 | period_1_hire |
| Увольнение 1 | period_1_dismissal |
| Начало работы 2 | period_2_hire |
| Увольнение 2 | period_2_dismissal |
| Начало работы 3 | period_3_hire |
| Увольнение 3 | period_3_dismissal |
| Срок окончания паспорта | passport_until |

### Правила

1. UUID в файле **не используется** и не должен присутствовать в шаблоне. Для новых сотрудников UUID генерируется системой.
2. Повторный импорт сопоставляет сотрудников по нормализованному ФИО.
3. Если найдено несколько кандидатов с одним ФИО, строка помечается как `ambiguous` — пользователь выбирает: создать нового, обновить конкретного кандидата или пропустить.
4. Для нового сотрудника в ячейке «ВУЗ» обязательно указать `Да` или `Нет`. Пустая ячейка при обновлении не затирает уже сохранённое значение.
5. Повторный импорт не создаёт дубликаты паспортов и записей грейда с теми же датами.
6. Грейды (`Грейд по должности`, `Фактический грейд`) сопоставляются со справочником без учёта регистра. Неизвестные значения не создаются автоматически: после проверки они попадают в `unknown_grades`, а в строках появляется предупреждение. Подтверждение импорта блокируется, пока каждый неизвестный грейд не заведут в справочнике (администратор или HR) или явно не пропустят. После заведения грейда нужно повторно проверить job (`POST /api/import/<id>/revalidate`), чтобы он распознался.
7. Награды за стаж (10/15/20 лет) при подтверждении отмечаются автоматически, если стаж уже достаточный: вехи рассчитываются по **суммарному** стажу всех периодов работы в компании (перерывы не входят), а автоотметка «получено» возможна только когда непрерывный стаж **текущего** периода тоже достиг вехи. Управляется опциями confirm:
   - `mark_reached_tenure` (по умолчанию `true`) — включает автоотметку для **создаваемых** сотрудников;
   - `update_existing_tenure` (по умолчанию `true`) — распространяет автоотметку и на **обновляемых** (существующих) сотрудников. Также при обновлении перезаписывается дата начала работы из файла и пересчитываются даты вех, которые ещё не отмечены как полученные.
   Уже отмеченные ранее награды не изменяются (ручные решения HR сохраняются). Количество проставленных наград возвращается в отчёте как `tenure_marked`.
8. Периоды работы (до 3): если сотрудник работал в компании с перерывами, заполните пары колонок **Начало работы N** / **Увольнение N**. Для завершённых периодов укажите обе даты; для текущего периода **Увольнение** оставьте пустым. Перед следующим периодом предыдущий должен быть закрыт датой увольнения. Импорт не удаляет уже заведённые периоды — при обновлении сотрудника нужно указать все периоды целиком.
9. После проверки обязателен confirm; в ответе приходит полный отчёт: создано / обновлено / пропущено (с причинами).

### Экспорт

`GET /api/import/template?import_type=employees` → `employees_template.xlsx`

## Поощрения (`import_type=rewards`)

### Обязательные колонки

| Колонка | Поле | Описание |
|---|---|---|
| ФИО | full_name | Должен совпасть с существующим сотрудником |
| Вид поощрения | reward_type | Название вида поощрения |

### Дополнительные колонки

| Колонка | Поле | Описание |
|---|---|---|
| № п/п | row_num | |
| Состояние | status | `Не вручено` / `В кадрах` / `Вручено` / `Доп. статус 1–3` (или коды `not_delivered` / `in_hr` / `delivered` / `extra_1` / `extra_2` / `extra_3`) |
| Указание на вручение | directive_text | |
| Дата вручения | delivered_date | Формат даты как в общей таблице |
| Примечание | notes | |

### Правила

1. Импорт поощрений **не создаёт** новых сотрудников. Если ФИО не найдено — строка с ошибкой.
2. Сопоставление сотрудника — по нормализованному ФИО.
3. Если найдено несколько сотрудников с одним ФИО, строка `ambiguous` — нужно выбрать кандидата или пропустить.
4. Повторный импорт обновляет существующее поощрение того же вида у сотрудника (сопоставление без учёта регистра). Если такого вида ещё нет — создаётся новая запись.
5. Пустое состояние трактуется как `Не вручено`.
6. После проверки обязателен confirm.

### Экспорт

`GET /api/import/template?import_type=rewards` → `rewards_template.xlsx`

## Форматы дат

Поддерживаются:

- `ДД.ММ.ГГГГ` (например `14.11.2026`)
- длинный русский формат `14 ноября 2026 г.` / `14 ноября 2026`
- ячейки Excel с типом «дата»

## API

- `POST /api/import/upload` — multipart: `file`, опционально `import_type` (`employees` | `rewards`, по умолчанию `employees`), `company_id`
- `POST /api/import/<id>/revalidate` — пересчитывает неизвестные грейды по текущему справочнику (после заведения грейда на месте)
- `POST /api/import/<id>/confirm` — `{ "row_actions": { "<rowId>": "create|skip|update:<uuid>" }, "mark_reached_tenure": true, "update_existing_tenure": true }` (последние два поля — только для `import_type=employees`)
- `GET /api/import/template?import_type=...`

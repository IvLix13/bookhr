# План: пофамильная выгрузка поощрений в Excel с выбором состояния

Дата: 14.10.2026  
Репозиторий: `IvLix13/bookhr`

## Цель

Добавить в модуль «Поощрения» отдельную пофамильную Excel-выгрузку, которая формируется из записей поощрений и перед скачиванием позволяет HR выбрать состояние поощрения.

По умолчанию выгружаются записи со всеми состояниями. Если HR выбирает конкретное состояние, в Excel попадают только записи с этим состоянием.

Функция должна быть доступна из существующего модального окна «Статистика поощрений».

## Текущее состояние

Сейчас в модуле «Поощрения»:

- отображается серверная таблица поощрений;
- таблица содержит ФИО, вид поощрения, состояние, дату изменения, указание на вручение, дату вручения и примечание;
- существует модальное окно «Статистика поощрений»;
- существует Excel-выгрузка агрегированной статистики по состояниям;
- backend уже использует `openpyxl` для формирования Excel;
- endpoint `/api/rewards` уже поддерживает фильтрацию по `status`;
- доступ к модулю и статистике ограничен ролями `ADMIN` и `HR`.

## Пользовательский сценарий

1. HR открывает раздел «Поощрения».
2. Нажимает кнопку «Статистика».
3. Открывается существующее модальное окно «Статистика поощрений».
4. В модальном окне появляется дополнительная кнопка «Выгрузить пофамильно».
5. HR нажимает «Выгрузить пофамильно».
6. Открывается отдельное модальное окно «Пофамильная выгрузка».
7. В модальном окне отображается поле «Состояние».
8. По умолчанию выбрано значение «Все состояния».
9. HR может выбрать конкретное состояние поощрения.
10. HR нажимает «Скачать Excel».
11. Backend формирует Excel-файл только с подходящими записями.
12. Браузер начинает скачивание файла.

## Список состояний

Список должен соответствовать текущим состояниям `RewardStatus` и их пользовательским подписям:

- Все состояния — специальное значение только для выгрузки;
- Не вручено;
- В кадрах;
- Вручено;
- Доп. статус 1;
- Доп. статус 2;
- Доп. статус 3.

Не дублировать пользовательские подписи вручную в нескольких местах, если их можно получить из уже существующей логики проекта.

## UX модального окна

### Модальное окно «Статистика поощрений»

Существующую статистику не менять.

В блок действий добавить кнопку:

- `Выгрузить пофамильно`.

Существующая выгрузка агрегированной статистики должна продолжить работать без изменений.

### Модальное окно «Пофамильная выгрузка»

Содержимое:

- заголовок `Пофамильная выгрузка`;
- поле `Состояние`;
- выпадающий список состояний;
- значение по умолчанию `Все состояния`;
- кнопка `Отмена`;
- кнопка `Скачать Excel`.

Поведение:

- при открытии модалки состояние всегда сбрасывается на `Все состояния`;
- `Отмена` закрывает только модалку пофамильной выгрузки;
- после закрытия HR должен остаться в модальном окне статистики;
- `Escape` должен корректно закрывать верхнюю открытую модалку;
- во время формирования/скачивания файла кнопку скачивания блокировать;
- показывать состояние загрузки, например `Скачивание…`;
- ошибку скачивания показывать внутри модального окна;
- повторное нажатие во время активной выгрузки не должно запускать второй запрос.

## Формат Excel

Excel должен представлять собой пофамильный снимок записей поощрений.

Колонки:

1. `ФИО`
2. `Вид поощрения`
3. `Состояние`
4. `Дата изменения`
5. `Указание на вручение`
6. `Дата вручения`
7. `Примечание`

Требования к данным:

- одна запись `Reward` = одна строка Excel;
- ФИО брать через текущую логику получения актуального имени сотрудника;
- состояние выводить русской пользовательской подписью, а не техническим значением `delivered`, `in_hr` и т. п.;
- пустые необязательные поля оставлять пустыми;
- даты выводить в читаемом формате `ДД.ММ.ГГГГ`;
- выгружать все подходящие записи, без серверной пагинации таблицы интерфейса.

Минимальное оформление:

- заголовки выделить жирным;
- закрепить строку заголовков;
- включить автофильтр;
- подобрать разумную ширину колонок;
- для длинных текстовых колонок включить перенос текста при необходимости.

## Фильтрация

### Все состояния

Если HR оставил `Все состояния`, параметр состояния в запросе не передавать либо передавать специальное значение, которое backend трактует как отсутствие фильтра.

В Excel должны попасть все поощрения текущей компании.

### Конкретное состояние

Если HR выбрал состояние, например `Вручено`, frontend передает его техническое значение, например:

```text
status=delivered
```

Backend должен проверить, что значение является допустимым `RewardStatus`, и применить фильтр:

```text
Reward.status == selected_status
```

### Область данных

Выгрузка всегда ограничивается `company_id` текущего пользователя через существующую tenant-логику.

В рамках данной задачи не связывать выгрузку с текущим поиском, сортировкой, пагинацией или column filters основной таблицы «Поощрения».

Результат зависит только от:

- текущей компании;
- выбранного состояния.

## Backend

### `backend/app/services/rewards.py`

Добавить отдельную функцию формирования пофамильного Excel, например:

```python
build_rewards_personalized_workbook(company_id: int, status: str | None = None) -> BytesIO
```

Задачи функции:

1. выбрать `Reward` только для текущей компании;
2. при наличии `status` отфильтровать записи;
3. загрузить необходимые связи с `Employment`/`Person`, избегая лишних запросов по возможности;
4. получить актуальное ФИО сотрудника через существующую доменную логику;
5. сформировать workbook через `openpyxl`;
6. преобразовать техническое состояние в пользовательскую подпись через `REWARD_STATUS_LABELS`;
7. заполнить строки Excel;
8. применить минимальное оформление;
9. вернуть `BytesIO` с файлом.

Не изменять существующую `build_reward_statistics_workbook()` — агрегированная статистика должна остаться отдельной функцией.

### `backend/app/api/rewards.py`

Добавить отдельный endpoint, например:

```text
GET /api/rewards/export
```

Query parameter:

```text
status=<RewardStatus>
```

`status` необязательный.

Логика:

- доступ только `ADMIN` и `HR`;
- определить `company_id` через `get_request_company_id()`;
- если `status` передан — проверить его через `RewardStatus`;
- при неизвестном состоянии вернуть `400`;
- вызвать сервис формирования Excel;
- вернуть файл через `send_file`;
- MIME type:
  `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`;
- имя файла, например `rewards_personalized.xlsx`.

При необходимости имя файла можно уточнять состоянием, но это не является обязательной частью задачи.

## Критерии приемки

Фича считается готовой, если:

- HR открывает «Статистика поощрений»;
- видит кнопку `Выгрузить пофамильно`;
- открывает отдельную модалку выбора состояния;
- по умолчанию выбрано `Все состояния`;
- может выбрать конкретное состояние;
- после `Скачать Excel` получает корректный `.xlsx`;
- без выбранного фильтра файл содержит все поощрения текущей компании;
- при выбранном состоянии файл содержит только соответствующие записи;
- файл содержит ФИО и остальные колонки таблицы поощрений;
- технические значения статусов не показываются пользователю;
- данные других компаний не попадают в файл;
- существующая статистика и ее Excel-выгрузка продолжают работать;
- миграция БД не требуется;
- backend и frontend тесты проходят.

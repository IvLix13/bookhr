## 1. Требования

1. В таблице обучения изменить CSS столбца sticky grade: min-width: 130px, max-width: 150px.
2. Перенести управление структурой таблицы в модальное окно.
3. Добавить тип столбца «Этап без даты»: только отметка выполнения, без плановой и фактической даты.
4. Добавить маркер «Не нужно» для этапа конкретного сотрудника.
5. Добавить обнуление отдельной ручной ячейки через «Очистить ячейку» и сохранение.
6. Транспонировать UI: сотрудник — столбец, этап/поле — строка. Это последующее требование заменяет прежнюю горизонтальную раскладку системных полей.

В разделах ниже «столбец» означает сущность структуры API (`OnboardingColumn`); в новом интерфейсе она отображается строкой. Идентификаторы и данные при транспонировании не меняются.

Остальные правила существующего модуля сохраняются: структуру и значения меняют HR/admin, viewer читает, данные разделены по компаниям, изменения записываются в аудит и защищены версиями.

## 3. Правила новых состояний

Трактовка для реализации: «Не нужно» относится к одной ячейке одного сотрудника, а не ко всему столбцу. Маркер доступен обоим типам этапов: с датами и без дат. Для текста, обычной даты и системных столбцов не добавляется.

| Тип | Не выполнено | Выполнено | Не нужно |
| --- | --- | --- | --- |
| Этап с датами (stage) | Плановая дата или прочерк | Зелёная галочка и фактическая дата | Нейтральная надпись «Не нужно» |
| Этап без даты (checkbox) | Пустая отметка / «Не выполнено» | Зелёная галочка без даты | Нейтральная надпись «Не нужно» |

Правила переходов — предлагаемые рабочие решения для этого плана:

- «Выполнено» и «Не нужно» взаимоисключающие состояния.
- В редакторе показать выбор одного из трёх состояний, чтобы нельзя было случайно выставить оба.
- Установка «Не нужно» снимает выполнение и очищает текущую фактическую дату. Старые значения остаются в аудите.
- Для stage плановый срок при этом сохраняется в БД; в таблице он скрыт надписью «Не нужно». В редакторе можно показать сохранённый срок как неактивный.
- При снятии «Не нужно» этап становится невыполненным; прежний срок восстанавливается на экране. Предыдущее выполнение автоматически не восстанавливается.
- Перевод из «Не нужно» в «Выполнено» снимает маркер; для stage нужна дата выполнения с обычной подстановкой сегодняшней даты и возможностью исправления.
- Для checkbox даты всегда отсутствуют: они не запрашиваются, не подставляются и не сохраняются как бизнес-значения. Технические timestamps и аудит остаются.
- «Не нужно» не считается просрочкой или выполнением. При отображении надпись имеет приоритет над датами, цветом выполнения и просрочкой.
- Новые ячейки: is_completed=false, is_not_required=false. Отсутствующая запись трактуется так же.
- Возврат любого этапа в нужное состояние доступен HR/admin через редактор.

Автоматическое преобразование существующих заполненных столбцов в checkbox не включать: текущий запрет смены типа при наличии данных сохраняется. Новый тип выбирается при создании столбца либо для пустого столбца.

## 6. Backend и модель

### Новый тип и маркер

- Добавить field_type=checkbox с пользовательским названием «Этап без даты».
- В OnboardingCell добавить is_not_required: Boolean, NOT NULL, default=false.
- Расширить ColumnSchema, ColumnUpdateSchema, CellSchema.
- В cell_dict включить is_not_required, в том числе для пустой ячейки.
- В save_cell разрешать поля по типу:
  - text: text_value;
  - date: date_value;
  - stage: planned_date, is_completed, completed_date, is_not_required;
  - checkbox: is_completed, is_not_required.
- Для checkbox отклонять передачу дат; не создавать скрытую дату выполнения.
- Для stage сохранять обязательность фактической даты при выполнении.
- Проверять состояние после объединения PATCH с существующей ячейкой. Обработку переходов в «Не нужно» и обратно сделать явной.
- Противоречивый запрос, одновременно требующий выполнение и «Не нужно», отклонять с понятной ошибкой.
- Маркер «Не нужно» считать заполненными данными при запрете смены типа, включая архивные ячейки.
- Сохранять аудит старых/новых значений, версии ячейки и столбца, блокировку компании, роли и CSRF.

### Ограничения БД

- Расширить ck_onboarding_column_type новым типом.
- Переработать ck_onboarding_completion: общий CHECK ячейки больше не может требовать дату при любом is_completed=true, так как тип хранится в другой таблице.
- Сохранить общий инвариант: при is_completed=false фактическая дата отсутствует.
- Добавить CHECK, запрещающий is_completed=true вместе с is_not_required=true.
- Типоспецифичные правила (stage требует дату, checkbox запрещает даты, text/date запрещают маркер) строго проверять в сервисе перед записью. Не оставлять прежний CHECK, блокирующий checkbox.
- Не добавлять SQL-подзапрос к таблице столбцов внутрь CHECK.

### Миграция

- Создать новую Alembic-ревизию от актуальной головы миграций на момент реализации; уже применённую 0016_onboarding.py не редактировать.
- Добавить is_not_required с false для всех существующих строк; существующие значения, сроки, статусы и даты не изменять.
- Обновить ограничения в PostgreSQL и обеспечить работу миграционного теста SQLite (при необходимости batch_alter_table).
- При downgrade заранее проверить наличие checkbox-столбцов или маркеров «Не нужно» и остановиться с понятным сообщением, если откат приведёт к потере данных. Не подставлять вымышленные даты ради старого ограничения.

## 8. Очистка ячейки

- Доступна HR/admin для text/date/stage/checkbox; системные данные не очищаются.
- Кнопка в редакторе только готовит очистку. «Отменить очистку» возвращает ввод; «Сохранить» отправляет clear=true с версиями ячейки и поля.
- Сервер сбрасывает значение и все даты в null, is_completed/is_not_required в false.
- Смешивать clear=true с изменением значения запрещено. Роли, компания, архив и версии проверяются обычным путём.
- Ячейка остаётся пустой с увеличенной версией: старый редактор не может перезаписать её, в том числе после повторной очистки. Аудит содержит действие clear и старые/новые значения.

## 10. Проверки и критерии приёмки

Backend:

- checkbox создаётся, сохраняется, отмечается и снимается без дат;
- stage по-прежнему требует дату выполнения;
- неверные поля, даты у checkbox и противоречивые состояния отклоняются;
- «Не нужно» работает индивидуально у разных сотрудников для одного столбца;
- все переходы сохраняются после повторной загрузки;
- срок stage не теряется при «Не нужно», фактическая дата очищается, предыдущее значение есть в аудите;
- нельзя сменить тип столбца, если в нём только отметки «Не нужно»;
- версии, архивирование, восстановление, права HR/admin/viewer, CSRF и компании сохраняют поведение;
- upgrade на БД с существующими выполненными и невыполненными этапами не меняет их значения;
- безопасный downgrade на данных старого формата и отказ от потери новых данных.

Frontend:

- модальное окно открывается/закрывается, удерживает фокус, сохраняет операции и корректно обрабатывает ошибки;
- несохранённый ввод не пропадает при случайном закрытии;
- новый тип доступен при настройке столбца;
- checkbox не показывает и не отправляет даты;
- «Не нужно» имеет отдельное отображение без зелёной галочки и просрочки;
- сотрудники отображаются столбцами, этапы строками; открывается ячейка выбранного сотрудника и этапа;
- старые текстовые поля, даты и этапы продолжают работать.

Команды: backend pytest; frontend npm run typecheck, npm test, npm run build.
Визуально проверить широкую таблицу и модальное окно. Старые несвязанные падения тестов отделять от новых регрессий.

Результаты: все 168 frontend-тестов прошли; typecheck и production build успешны. Backend: 298 passed, 4 failed; все 39 тестов onboarding прошли. Четыре прежних падения воспроизведены на исходной версии и относятся к test_employees_list, test_grade_policy_migration, test_import_excel и test_tenure_events_api. Визуальная проверка не выполнена: политика безопасности браузера отклонила доступ к локальному адресу. PostgreSQL/prod не развёртывались; миграция проверена на SQLite.

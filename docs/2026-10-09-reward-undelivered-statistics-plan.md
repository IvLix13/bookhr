## 1. Цель и правило расчёта

Итоговый показатель «Не вручено» должен означать все поощрения, которые сейчас не имеют статуса delivered:

- Всего = количество всех поощрений текущей компании.
- Вручено = количество поощрений со статусом delivered.
- Не вручено = Всего − Вручено.

В итог входят not_delivered, in_hr, extra_1, extra_2, extra_3 и любые другие состояния, включая неизвестные/пустые значения в старых данных, если такие записи существуют. Дата вручения не определяет принадлежность к итогу: источник истины — текущий статус.

Пример: всего 100, delivered 40, not_delivered 10, in_hr 20, дополнительные состояния 30. Итог «Не вручено» = 60.

## 2. Проверенная текущая реализация

- backend/app/services/rewards.py: reward_status_statistics(company_id) группирует Reward.status, ограничивает выборку через Employment.company_id, возвращает items и total. В items not_delivered содержит только записи этого конкретного состояния; неизвестные состояния также добавляются.
- Там же build_reward_statistics_workbook использует результат этой функции и выгружает items и total в Excel.
- backend/app/api/rewards.py: /rewards/statistics и /rewards/statistics/export доступны ADMIN и HR.
- frontend/src/views/RewardsView.vue отображает items как состояния и total внизу таблицы.
- frontend/src/types/index.ts: RewardStatistics сейчас содержит items и total; frontend/src/api/client.ts уже использует этот тип.
- Состояния поощрений и их подписи описаны в backend/app/models/reward.py и frontend/src/utils/statuses.ts.

Этот план относится к разделу поощрений на модели Reward. Отдельный раздел наград за стаж не менять.

## 3. Backend и контракт API

1. Сохранить items как точную, непересекающуюся разбивку по текущим состояниям. Не заменять count состояния not_delivered агрегатом.
2. Считать total по всем результатам группировки в той же выборке компании.
3. Добавить в ответ числовые поля delivered и undelivered:
   - delivered = counts.get(RewardStatus.DELIVERED.value, 0);
   - undelivered = total − delivered.
4. Возвращать целые числа; для пустой выборки все итоги равны нулю.
5. Считать всё из результатов существующего запроса, без отдельных запросов на каждый показатель.
6. Сохранить включение неизвестных состояний в items и total.
7. Не менять фильтрацию по компании, права доступа и маршруты. Итоги, как сейчас, относятся ко всей компании, независимо от поиска и страницы основной таблицы.

Контрольные равенства: total = sum(items.count), total = delivered + undelivered.
Итоги нельзя суммировать с разбивкой по состояниям: они описывают те же записи.

## 4. Интерфейс

1. Дополнить RewardStatistics полями delivered: number и undelivered: number.
2. В модальном окне статистики показать отдельный блок итогов: «Всего», «Вручено», «Не вручено».
3. Ниже оставить текущую таблицу с явным заголовком «Разбивка по состояниям».
4. Для строки not_delivered только в этой таблице использовать подпись «Состояние: Не вручено», чтобы её точное количество нельзя было принять за общий итог.
5. Добавить краткое пояснение: «Не вручено — все поощрения, кроме состояния “Вручено”».
6. Использовать итоги API, не пересчитывать их на клиенте и не суммировать итог с детализацией.
7. Сохранить загрузку, обработку ошибок, повторный запрос, закрытие окна и скачивание Excel.

Не менять подпись и смысл статуса not_delivered в формах, основной таблице, фильтрах и импорте.

## 5. Excel

1. Использовать ту же reward_status_statistics, что и API.
2. Разместить отдельный блок итогов «Всего / Вручено / Не вручено».
3. Отдельно разместить разбивку по состояниям; строку not_delivered подписать «Состояние: Не вручено».
4. Добавить то же пояснение смысла агрегата.
5. Сохранить формат XLSX и имя rewards_statistics.xlsx; оформить заголовки и ширину столбцов для читаемости.
6. Не складывать итоги и строки детализации при расчёте общего количества.

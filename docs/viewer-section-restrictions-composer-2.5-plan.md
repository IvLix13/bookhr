## 1. Требование и ожидаемое поведение

Пользователь с ролью `viewer` не должен иметь доступа к разделам:

1. «Импорт данных» — обе вкладки: сотрудники и поощрения.
2. «Поощрения».
3. «Статистика» — автоматическая и ручная.
4. «Награды за стаж».

Запрет включает скрытие пунктов навигации, блокировку открытия страниц по прямой ссылке и отказ API в выдаче данных, результатов импорта, шаблонов и экспортируемых файлов этих разделов. Одного скрытия меню недостаточно.

| Роль | Четыре перечисленных раздела | Остальные разделы |
| --- | --- | --- |
| viewer | Нет меню, нет доступа к страницам, API возвращает 403 | Существующие права сохраняются |
| hr | Существующий доступ сохраняется | Существующие права сохраняются |
| admin | Существующий доступ сохраняется | Существующие права сохраняются |
| Без авторизации | Существующий вход/401 | Существующее поведение |

`viewr` в формулировке задачи означает существующую роль `viewer`; новую роль не создавать.

## 2. Подтверждённое текущее состояние

### Роли и механизмы проверки

- `backend/app/models/user.py`: роли `admin`, `hr`, `viewer`; `User.can_edit()` разрешает admin/hr.
- `backend/app/api/helpers.py`: `require_roles(RoleName.ADMIN, RoleName.HR)` уже включает `login_required` и возвращает `api_response(message="Forbidden", status=403)` при недостаточных правах.
- `frontend/src/stores/auth.ts`: `auth.canEdit()` разрешает admin/hr.
- `frontend/src/router/index.ts`: guard проверяет `requiresEdit` через `to.matched.some(...)`, при отказе направляет в `calendar` с `denied=edit`. До проверки прав он восстанавливает пользователя через `fetchMe()`.
- `frontend/src/config/sidebarNav.ts`: пункты могут скрываться через `isVisible(auth)`; это использует `Sidebar.vue`.

### Страницы и API

| Раздел | Маршруты интерфейса | Файлы API | Текущее ограничение |
| --- | --- | --- | --- |
| Импорт данных | /import, /import/employees, /import/rewards | backend/app/api/import_api.py | Родительский маршрут имеет requiresEdit, но пункт меню не скрыт; GET результата и шаблонов требует только входа |
| Поощрения | /rewards | backend/app/api/rewards.py | Чтение списка, статистики и экспорта требует только входа |
| Статистика | /statistics | backend/app/api/stats.py | Автоматическая, ручная статистика и ручной шаблон требуют только входа |
| Награды за стаж | /awards | backend/app/api/modules.py | AwardsView.vue читает /api/tenure; GET требует только входа |

Пункты `rewards`, `awards`, `import-employees`, `statistics` в конфигурации меню сейчас не имеют `isVisible`.
Маршруты `rewards`, `awards`, `statistics` сейчас не имеют `requiresEdit`.
Запись в этих API уже ограничена admin/hr.

Часть текущих тестов явно ожидает успешное чтение viewer:
- `backend/tests/test_stats.py`: `test_stats_api_viewer_can_read`.
- `backend/tests/test_manual_statistics.py`: чтение пустого/старого снимка и шаблона через viewer.
- `backend/tests/test_rewards.py`: `test_reward_statistics_export_for_viewer`.
- `backend/tests/test_tenure_listing.py`: GET, поиск, пагинация через viewer.

Эти ожидания необходимо адаптировать, сохранив проверку функциональности для разрешённых ролей.

## 3. Границы задачи — обязательные указания Composer 2.5

Реализовать только этот план. Сначала сверить его с текущим кодом и прочитать применимые `AGENTS.md`, если они появились после проверенного коммита. В проверенном дереве репозитория `AGENTS.md` отсутствуют.

Не добавлять новую систему ACL, переключатели режима доступа, настройки разделов, новые роли, зависимости или редизайн. Использовать существующие `canEdit`, `requiresEdit`, `isVisible` и `require_roles`.

Не менять глобально `login_required`, общий Blueprint или все маршруты `modules.py`: там находятся также договоры, грейды и паспорта, которые в задачу не входят. Не менять текущие ограничения настроек и плана обучения.

Не менять расчёты статистики и стажа, поиск, пагинацию, формат Excel, обработку импорта, tenant-фильтрацию и данные существующих пользователей. Не переименовывать роли. Миграции БД не нужны.

Это запрет доступа к четырём разделам и их специализированным API. Он не означает автоматический запрет любой информации о наградах в карточках сотрудников, календаре или событиях. Эти общие разделы остаются в текущем объёме доступа. Проверить их зависимости, чтобы они не запрашивали теперь запрещённые API безусловно. Если такая зависимость обнаружена, убрать именно недоступный вызов/ссылку для viewer с минимальным изменением и описать это в отчёте. Не вводить без отдельного требования фильтрацию общей карточки или календаря по типам данных.

### Шаг 2. Скрыть пункты меню для viewer

В `frontend/src/config/sidebarNav.ts` добавить `isVisible: (auth) => auth.canEdit()` четырём пунктам:
- `rewards`;
- `awards`;
- `import-employees`;
- `statistics`.

Сохранить порядок, подписи, изображения, активные состояния и выбор вкладок.
Не дублировать фильтрацию в шаблоне Sidebar.vue: текущая фильтрация через конфигурацию достаточна.
Проверить свёрнутое и развёрнутое меню.

### Шаг 3. Заблокировать прямые переходы

В `frontend/src/router/index.ts` добавить `meta: { requiresEdit: true }` маршрутам `rewards`, `awards`, `statistics`.

У родительского `import` сохранить существующий `requiresEdit`; не дублировать guard на каждой дочерней странице. Проверить /import и обе дочерние ссылки.

Использовать существующее перенаправление в `calendar` с `denied=edit`. Не добавлять новую страницу отказа или отдельный механизм авторизации.
При входе viewer по сохранённой ссылке и при обновлении страницы решение должно приниматься после восстановления пользователя.
Защита не должна запускать запросы данных запрещённой страницы до перенаправления.

### Шаг 4. Закрыть чтение на сервере

Заменить `@login_required` на `@require_roles(RoleName.ADMIN, RoleName.HR)` у следующих обработчиков:

| Файл | Метод и endpoint | Обработчик |
| --- | --- | --- |
| backend/app/api/import_api.py | GET /api/import/<job_id> | get_job |
| backend/app/api/import_api.py | GET /api/import/template | download_template |
| backend/app/api/rewards.py | GET /api/rewards | list_rewards |
| backend/app/api/rewards.py | GET /api/rewards/statistics | reward_statistics |
| backend/app/api/rewards.py | GET /api/rewards/statistics/export | reward_statistics_export |
| backend/app/api/stats.py | GET /api/stats | stats |
| backend/app/api/stats.py | GET /api/stats/manual | manual_stats |
| backend/app/api/stats.py | GET /api/stats/manual/template | manual_stats_template |
| backend/app/api/modules.py | GET /api/tenure | list_tenure |

Декоратор должен отказать до чтения/сериализации данных, разбора query-параметров, генерации Excel и обращения к заданию импорта. Отказ одинаков для существующих и несуществующих job_id: viewer не должен узнавать существование задания.

GET шаблона импорта закрыть для обоих `import_type=employees` и `import_type=rewards`, включая значение по умолчанию.

Сохранить действующие ограничения POST/PATCH:
- загрузка, подтверждение и перепроверка импорта;
- создание и изменение поощрений;
- загрузка ручной статистики;
- изменение награды за стаж.

Не накладывать второй `login_required`: он уже находится внутри `require_roles`.
Удалить только действительно неиспользуемые импорты. В `modules.py` оставить `login_required`, потому что он нужен другим обработчикам.

- viewer: четырёх пунктов нет в меню; прямые ссылки и reload ведут на календарь;

- admin/hr: разделы открываются, списки загружаются, шаблоны и экспорт скачиваются;
- после отказа viewer остаётся авторизованным и работает в разрешённых разделах.

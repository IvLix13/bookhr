## Цель и границы

Обновить окно существующего плана каждого сотрудника в стиле BookHR:

1. Выразительно оформить ФИО, грейд, наставника и прогресс по выбранному варианту «Карточки сведений».
2. Увеличить максимальную ширину окна плана до 1500 px.
3. Перенести нижние действия в меню «Бургер» рядом с крестиком; убрать нижнюю панель кнопок основного окна.
4. Визуально усилить столбец «Этап / поле».
5. Переместить «Состояние / значение» в крайний правый столбец; выполненные строки целиком выделять зелёным.
6. Сделать таблицу прокручиваемой, закрепить её заголовки и добавить поиск по строкам.

Область реализации — окно ведения уже сохранённого плана, открываемое из списка сотрудников. Мастер создания и его предварительная проверка в `OnboardingCreateView.vue` остаются отдельным сценарием. Новые API, изменения модели, миграции и зависимости для этой задачи не требуются.

## Внешний вид выбранного варианта

### Заголовок и размеры

- Заголовок окна — «План сотрудника»; полное ФИО находится в сводке ниже. Сохранить доступное имя диалога и связать сведения о сотруднике с диалогом.
- Справа последовательно расположить кнопку меню «☰» и крестик. Обе кнопки остаются доступны при прокрутке таблицы.
- Ширина основного окна: `min(1500px, 100%)` относительно области overlay с отступами от краёв экрана. На экране 1920 px окно достигает 1500 px; на 1440 px помещается в доступную ширину без прокрутки страницы по горизонтали.
- Ограничить высоту доступной высотой viewport с внешними отступами, используя действующий подход с `100dvh`.

### ФИО и карточки сведений

Сначала показать ФИО крупным заголовком. Под ним — отдел и дату прибытия. Ниже расположить три карточки в одну строку на desktop:

| Карточка | Содержание | Оформление |
| --- | --- | --- |
| Грейд | Подпись «Грейд» и актуальное значение | Компактная карточка; значение выделено синим акцентом |
| Наставник | Подпись «Наставник» и полное ФИО | Более широкая карточка с переносом длинного ФИО |
| Выполнение плана | Процент, сегментированная полоса, «Выполнено N из M этапов» | Зелёный сегмент выполненного, жёлтый работы, красный просрочки, серый остаток |

ФИО, грейд и наставник берутся из загруженного плана; отдел и прибытие — из существующего `planSummary`. Не подставлять демонстрационные значения из макета в приложение.

Пустые значения: «Сотрудник», «Грейд не назначен», «Не назначен», «Отдел не указан». Отсутствующие даты форматировать существующим `formatShortDate`. При отсутствии обязательных этапов показывать 0% и «Нет обязательных этапов».

Прогресс рассчитывать по полному набору активных полей, независимо от поиска: только `stage` и `checkbox`, без `not_required`. Сохранить существующее округление и приоритет просрочки по московской дате. Полоса должна иметь `role="progressbar"`, числовые ARIA-атрибуты и текстовое описание результата.

### Соответствие стилю приложения

Использовать `--surface`, `--bg`, `--text`, `--muted`, `--border`, `--accent`, `--accent-soft`, существующие радиусы, тень и шрифт Inter / Segoe UI / system-ui. Основа — белое окно, светло-серые карточки, синий акцент и спокойные цветные статусы. Не добавлять внешние шрифты, CDN, библиотеки значков или новые npm-пакеты: решение должно работать в офлайн-контуре.

## Меню действий

Добавить в `OnboardingDialog.vue` именованный слот, например `header-actions`, непосредственно перед крестиком. Оболочка отвечает за размещение слота; состав действий и права остаются в `OnboardingPlanModal.vue`.

| Пункт | Доступ и поведение |
| --- | --- |
| Выгрузить план | Существующая выгрузка DOCX `api.downloadOnboardingDocx`; сохранить доступность для действующих ролей и защиту от повторной выгрузки |
| Изменить наставника | Только HR/admin; открыть существующий сценарий изменения `curator_name` |
| Удалить план | Только HR/admin; открыть `OnboardingDeleteDialog`, удаление выполняется после подтверждения |
| Удалить сотрудника и план | Только HR/admin; открыть существующее отдельное подтверждение удаления периода трудоустройства с планом |
| Закрыть окно | Тот же обработчик защищённого закрытия, что используется крестиком |

Удаления визуально отделить от обычных действий и выделить цветом опасного действия. Убрать из основного окна прежние нижние кнопки выгрузки, удаления и закрытия, а также отдельную кнопку изменения куратора над таблицей.

Меню открывать кнопкой с `aria-label="Действия с планом"`, `aria-expanded` и `aria-controls`. Использовать раскрывающуюся панель с обычными кнопками и естественным Tab-порядком. Не присваивать панели `role="menu"` без реализации соответствующей навигации стрелками.

Закрывать панель при выборе действия, клике вне панели и Escape. Escape при открытом меню сначала закрывает меню, не закрывая диалог. Возвращать фокус кнопке меню; после открытия вложенного диалога фокус получает этот диалог. Панель должна иметь непрозрачный фон, располагаться выше таблицы и не обрезаться её scroll-контейнером.

Сохранить блокировки операций при загрузке, ошибке загрузки, сохранении, несохранённом вводе и открытых вложенных редакторах согласно текущим обработчикам. Для выгрузки учитывать `exporting`; сообщение об ошибке выгрузки остаётся видимым в основном окне после закрытия меню. Крестик и пункт закрытия используют одну проверку dirty/busy.

Форму показывать в области сводки перед таблицей; кнопки «Сохранить наставника» и «Отмена» относятся к этой форме, а не к удаляемой нижней панели действий плана.

В интерфейсе окна использовать термин «Наставник». В API и типах сохранить `curator_name`, текущую версию плана и ограничение длины 256 символов. Сохранить обрезку крайних пробелов, передачу `null` для пустого значения, обработку 409 без потери ввода и запрет повторного сохранения устаревшей версии. Успешное сохранение обновляет сводку и карточку списка, оставляя план открытым.

## Таблица и поиск

Итоговый порядок столбцов:

| Позиция | Заголовок |
| --- | --- |
| 1 | Этап / поле |
| 2 | Ответственный отдел |
| 3 | Плановый срок |
| 4 | Выполнено |
| 5 | Состояние / значение |

- Первый столбец сделать шире дат, усилить насыщенность текста и фон шапки, добавить спокойный фон ячеек. Длинные названия переносить, не обрезать.
- Для дат использовать согласованную ширину и табличные цифры. Сохранить правила показа плановых/фактических дат: у `checkbox` дат нет, у `not_required` срок скрыт, но сохранённое значение не очищается.
- Последний столбец содержит статус этапа либо значение `text`/`date`. Кнопка значения продолжает открывать существующий `OnboardingCellEditor`. Viewer получает доступ к редактированию только своего плана по текущему правилу; для остальных значений остаётся текст.
- Полную зелёную заливку применять к `tr` завершённых этапов обоих типов, включая `th` и все `td`. Проверять результат `stageState(...) === 'completed'`, чтобы `not_required` не получил зелёную заливку даже при противоречивых исходных флагах.
- На зелёной строке сохранить читаемость первого столбца, ответственного отдела, дат и статуса «Выполнено». Общие hover-стили не должны скрывать заливку. Состояния различаются также текстом, а не только цветом.
- Для «В работе», «Просрочено», «Не начато», «Не нужно» оставить спокойные метки в крайнем правом столбце; просроченный срок можно дополнительно выделить красным. Заполненное текстовое поле или обычная дата сами по себе не означают выполненный этап.

Над таблицей расположить «Этапы и данные плана», счётчик строк и поле «Поиск по таблице…» с доступным именем. Искать локально по названию этапа/поля, ответственному отделу, отображаемому состоянию/значению и отображаемым датам. Искать без учёта регистра, обрезая крайние пробелы запроса; использовать существующие форматировщики и подписи. При поиске по состоянию использовать видимое `stageLabels`, поскольку `cellLabel` отдельно не всегда совпадает с текстом статуса в таблице.

Поиск фильтрует только отображаемые строки и сохраняет исходный порядок. Он не меняет прогресс, структуру плана, список сотрудников, данные или содержимое DOCX. Показывать «Найдено: N из M», отдельное состояние «Ничего не найдено» и исходное «Этапы пока не настроены» при пустой структуре. После изменения запроса возвращать вертикальную прокрутку таблицы к началу.

При обновлении плана после сохранения сохранять текущий запрос и вычислять результат заново; при открытии другого плана начинать с пустого запроса. Скрытые поиском значения не очищать и не сохранять автоматически.

## Прокрутка и адаптивность

Добавить в общую оболочку опциональный режим компоновки, например `layout="plan"`. В обычном режиме сохранить текущие размеры и поведение остальных окон. В режиме плана:

1. Оболочка — flex-column с ограниченной высотой; заголовок не сжимается.
2. Область содержимого, обёртка плана и секция деталей передают доступную высоту вниз через `flex: 1`, `min-height: 0`, `min-width: 0`.
3. Сводка и строка поиска остаются над прокручиваемой таблицей.
4. Контейнер таблицы получает `overflow: auto`; использовать одну область прокрутки по обеим осям.
5. У `thead th` — `position: sticky`, `top: 0`, непрозрачный фон, нижняя граница и локальный `z-index` ниже меню.

Не ограничиваться `max-height` таблицы при сохранённой независимой прокрутке всего desktop-окна: при большом количестве строк должна прокручиваться таблица, а не уходить заголовок с меню.

На узком экране карточки складываются вертикально, поиск занимает доступную ширину, горизонтальная прокрутка ограничена таблицей. На очень низком viewport предусмотреть доступную внешнюю прокрутку как адаптивный fallback, чтобы сводка/форма наставника не вытеснили таблицу и действия за пределы окна. Проверить доступность всех элементов без обрезания. Изменения локальны окну плана и не затрагивают размеры подтверждений и других диалогов.

## Сохранение существующих сценариев

- Оставить текущие права HR/admin/viewer, проверку собственного плана и серверную авторизацию.
- Сохранить загрузку актуального плана по ID, обработку ошибок, обновление списка через `changed`, закрытие после `deleted` и существующую работу с версиями.
- Для ячеек использовать действующий `OnboardingCellEditor`; не переносить в рабочее приложение упрощённый редактор или переключение статусов из демонстрационного макета.
- Сохранить отдельные подтверждения обоих удалений и актуализацию после конфликтов.
- Сохранить focus trap верхнего диалога, возврат фокуса, блокировку прокрутки страницы и защиту несохранённого ввода. Изменять composables только при выявленной регрессии.
- Сохранить отображение загрузки, ошибок и повторной загрузки; меню не должно предоставлять операции над неактуальными данными при ошибке загрузки.
- Сохранить доступность информации об увольнении при её выводе; цветная полоса и новые карточки не меняют бизнес-состояние сотрудника.

## Результат реализации

Режим `layout="plan"` и слот `header-actions` добавлены в общую оболочку. Сводка, меню и версия формы наставника находятся в `OnboardingPlanModal.vue`; поиск, перестановка столбцов, подсветка завершённой строки и sticky header — в `OnboardingPlanDetails.vue`. Прежние API, редактор ячейки, подтверждения удаления и composables фокуса/прокрутки сохранены. Поиск переживает обновление данных того же плана. Escape сначала закрывает открытое меню, в том числе при фокусе в поиске, затем может закрыть диалог.

Проверки: `npm run typecheck`, 232 frontend-теста в 45 файлах и `npm run build` прошли. Сборка предупреждает о размере чанка статистики более 500 kB. Проверены сценарии формы наставника, 409, вложенных окон и прав; добавлены проверки поиска, завершённой строки/исключения, меню и повторной выгрузки.

Браузерная проверка размеров, цветов и sticky-позиционирования на перечисленных viewport не выполнена: в среде отсутствует Chromium, установка Playwright Chromium завершается ошибкой загрузки ZIP (`End of central directory record signature not found`). Unit-тесты и сборка не заменяют эту проверку. Последний пункт приёмки оставлен открытым до проверки в доступном браузере.

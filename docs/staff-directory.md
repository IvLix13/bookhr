# Синхронизация с внешним кадровым сервисом

BookHR получает должность и формальный отдел существующих сотрудников через `GET /staff/placement/public/`. Фоновые запросы выполняет сервер, API-ключ не попадает в браузер. Интеграция выключена по умолчанию.

## Какие данные обновляются

- `Person.cardnumber` — общий для компаний номер человека, строка с ведущими нулями, уникальная во всём BookHR.
- `Person.fio_short` — сокращённое ФИО.
- `PositionHistory.title` / `short_title` — полная и сокращённая должность.
- `Employment.formal_department_short_name` / `formal_department_name` — формальный отдел.

В API полная должность доступна одновременно как `title` и `position_name`. `position_short_name` соответствует `short_title`. В общей таблице есть колонка «Отдел», полное название видно в подсказке. Реквизиты доступны в карточке сотрудника с существующими правами admin/hr/viewer.

`staff_id`, `rank`, `rank_short`, фактический отдел игнорируются. Грейд по должности, фактический грейд, даты назначения и расчёты не меняются. Обновлённая должность автоматически используется существующими потребителями истории, включая DOCX. Отдел сотрудника не заменяет ответственный отдел этапа онбординга.

Сервис доверенный: при однозначном сопоставлении данные применяются без подтверждения. Ручные изменения этих реквизитов admin/hr допустимы; следующий проход сервиса может их заменить. Внешний сервис не создаёт и не увольняет сотрудников.

## Ограничение нагрузки

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `STAFF_DIRECTORY_ENABLED` | `false` | Включение интеграции |
| `STAFF_DIRECTORY_BASE_URL` | пусто | Базовый URL, без `/staff/placement/public/` |
| `STAFF_DIRECTORY_API_KEY` | пусто | Ключ для заголовка `X-Api-Key` |
| `STAFF_DIRECTORY_TIMEOUT` | `30` | Таймаут одного HTTP-запроса, секунды |
| `STAFF_DIRECTORY_BATCH_SIZE` | `100` | Размер получения идентификаторов из БД; не число параллельных HTTP-запросов |
| `STAFF_DIRECTORY_REQUEST_INTERVAL` | `2` | Минимальная пауза после завершения запроса; дополнительно случайные 0–0,5 с. Минимально допустимо 1 с |
| `STAFF_DIRECTORY_MIN_SYNC_HOURS` | `6` | Минимальный интервал между завершёнными проверками человека; минимум 1 час |
| `STAFF_DIRECTORY_MAX_RETRIES` | `2` | Дополнительные попытки при таймаутах/ошибках соединения/5xx, допустимо 0–5 |
| `STAFF_DIRECTORY_MAX_REQUESTS` | `500` | Максимум HTTP-попыток за проход, включая повторы |
| `STAFF_DIRECTORY_MAX_RUN_SECONDS` | `1800` | Бюджет времени прохода; отдельный уже начатый запрос может завершиться позже |

Обработка строго последовательная, потоков и массовых параллельных запросов нет. Пауза применяется также между повторами. Внутренние повторы HTTP-адаптера и переходы по редиректам отключены. При 150 сотрудниках первый проход займёт около 5–6 минут плюс время ответов. Для 160 запросов тест с виртуальным временем подтверждает минимум 318 секунд между первым и последним запросом при паузе 2 с без случайной добавки и сетевой задержки.

Техническая отметка `Person.staff_directory_checked_at` сохраняется в БД: перезапуск процесса и ручной запуск не отменяют шестичасовой интервал. Завершённые ответы «не найден», неоднозначное совпадение и конфликт тоже получают отметку, чтобы не повторять бесполезные запросы каждый час. Ошибки HTTP/БД её не обновляют. После смены полного ФИО, номера карточки и повторного приёма отметка сбрасывается.

Общая блокировка действует на все компании, CLI и dry-run одной базы: PostgreSQL advisory lock, для локальной SQLite — файловая блокировка Linux. Второй проход завершается с `already_running`. Это не координирует независимые установки BookHR с разными БД: их суммарный лимит нужно учесть отдельно.

При `429` проход прекращается сразу, без повторов. `Retry-After` (секунды или HTTP-дата) сохраняется в `staff_directory_state.blocked_until`; до этого времени следующие запуски не обращаются к API. При отсутствии корректного заголовка пауза не менее минуты. `503`/другие 5xx с `Retry-After` также останавливают проход на указанное время. После трёх подряд технических ошибок срабатывает остановка на 5 минут. При 401/403 проход останавливается, устанавливается часовая пауза. Значение `Retry-After` ограничено сверху одним годом для защиты от некорректного заголовка.

Ограничение количества попыток действует и при ошибках; исчерпание бюджета даёт `budget_exhausted`, оставшиеся люди будут проверены в следующем проходе. Уже успешно проверенные люди пропускаются до истечения интервала. Настройки не являются гарантией допустимой нагрузки: согласуйте лимит с владельцем API, при необходимости увеличьте паузу и интервал синхронизации.

## Сопоставление и пустые значения

1. Используется текущее полное ФИО BookHR в формате «Фамилия Имя [Отчество]». Без отчества параметр `patronymic` не отправляется. Инициалы и неоднозначные составные имена не разбираются догадками.
2. Для первичной привязки нужен единственный внешний результат с непустым номером. Если одинаковое полное ФИО принадлежит разным локальным людям, автоматической привязки нет.
3. После привязки из результатов выбирается строго сохранённый `cardnumber`. Другой номер не подменяет связь. Поиск непосредственно по номеру внешний контракт пока не предоставляет.
4. Если номер занят другим локальным `Person`, фиксируется конфликт без объединения людей.
5. Должность и отдел обновляются только у единственного активного трудоустройства человека. Фильтр компании этого правила не отменяет. Если активных трудоустройств несколько, обновляются только общие реквизиты человека; результат — `partial` или `ambiguous_employment`. В ответе сервиса нет компании для распределения размещений.
6. Пустой `people` не означает увольнение и не очищает карточку. Отсутствующий ключ сохраняет прежнее значение; явный NULL/пустая строка очищает описательное поле. Пустая полная должность отображается как «Не указана». Пустой номер не очищает существующую связь.

Неоднозначные соответствия выводятся в CLI с локальным `person_id`. После проверки правильного человека admin/hr может вручную задать номер в карточке: он проверяется на уникальность и попадает в аудит. Следующий поиск по полному ФИО должен вернуть этот номер. Если этого не происходит, сначала исправьте локальное ФИО или контракт внешнего API.

Сетевой запрос выполняется без открытой транзакции BookHR. Перед применением повторно проверяются ФИО, номер и активные трудоустройства. Устаревший ответ получает `stale`. Запись одного человека атомарна; неудача не отменяет ранее обработанных людей. Повтор одинакового ответа не создаёт историю должностей и аудит изменений заново.

## Установка и первый запуск

1. Обновить файлы приложения и выполнить миграции обычным способом: `./scripts/migrate.sh prod`. Новая миграция — `0025_staff_directory_fields` после `0024_onboarding_shared_mapping`.
2. В `.env.prod` задать URL, ключ и `STAFF_DIRECTORY_ENABLED=true`. Остальные настройки можно оставить по умолчанию.
3. Перезапустить основной сервис после миграции, собрать frontend.
4. Из каталога `backend` в том же окружении, что использует сервис, проверить:

```bash
flask sync-staff-directory --person-id 123 --dry-run
flask sync-staff-directory --company-id 1 --dry-run
flask sync-staff-directory --company-id 1
```

`--person-id` — локальный `Person.id`, а не `Employment.id` и не внешний `staff_id`. При сочетании фильтров человек должен работать в указанной компании. Все команды требуют загруженного окружения `.env.prod` и `FLASK_APP=wsgi:app`, как у существующих Flask CLI-команд.

Dry-run выполняет реальные ограниченные HTTP-запросы и показывает `before`/`after`, но не меняет БД, аудит и timestamps. Он учитывает уже сохранённые интервалы/общую паузу и не сохраняет новую отметку или новый cooldown. Поэтому не используйте dry-run в плотном цикле.

5. После проверки сопоставлений установить `deploy/bookuchet-staff-sync.service` и `.timer` в `/etc/systemd/system/`:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bookuchet-staff-sync.timer
sudo systemctl status bookuchet-staff-sync.timer
journalctl -u bookuchet-staff-sync.service
```

Timer запускает проверку раз в час в `:15 Europe/Moscow` со случайной задержкой до 5 минут. Из-за отметки последней проверки конкретный человек обычно обновляется раз в 6 часов. `TimeoutStartSec=35min` больше стандартного бюджета 30 минут; при увеличении бюджета настройте unit согласованно. Включать timer до проверки настроек не нужно.

Результаты CLI: `updated`, `unchanged`, `partial`, `not_found`, `ambiguous`, `ambiguous_local_name`, `invalid_local_name`, `missing_cardnumber`, `cardnumber_mismatch`, `cardnumber_conflict`, `ambiguous_employment`, `stale`; технические ошибки учитываются отдельно. Итог показывает фактическое число HTTP-попыток. Ненулевой код завершения означает техническую ошибку, а не отсутствие сотрудника. Отчёт содержит разрешённые реквизиты сотрудника; полный ответ внешнего сервиса, ключ и URL с параметрами в него не включаются.

## Офлайн-контур и откат

Новых зависимостей приложения нет: используется уже включённый `requests`. Нужна сетевая доступность внешнего сервиса именно с сервера BookHR; доступ к Интернету не требуется, если сервис находится в локальной сети. При полной изоляции оставьте интеграцию выключенной, карточки и остальные функции продолжат работать.

Для отключения остановите timer и выставьте `STAFF_DIRECTORY_ENABLED=false`. Остановка интеграции не очищает полученные данные. Перед откатом миграции остановите timer и сохраните резервную копию. Downgrade удаляет новые поля и технические отметки, но не восстанавливает прежние названия должностей: они доступны в истории/аудите либо резервной копии.
